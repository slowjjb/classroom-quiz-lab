# 퍼플킷 v4.12 — 구버전 학생 입장 방지

## 바뀐 기능
- 새로운 `version.json`을 학생과 교사 페이지에서 **캐시를 우회**해 확인합니다. v4.12 이상 학생이 오래된 탭으로 새 방에 들어가려 하면 새로고침 안내를 표시합니다.
- v4.12에서 만드는 새 방에 `minClientBuild: 412`, `minClientVersion: "4.12"`를 기록합니다.
- **v4.12 통합 Firebase Realtime Database 보안 규칙을 게시해야 합니다.** 신버전 방에서는 프로필에 `clientBuild`가 필요하고, 접속 세션에는 `{at,clientBuild}` 객체가 필요합니다. 구버전 v4.11 클라이언트는 해당 접속 세션을 생성하지 못합니다.
- 새로운 보안 규칙이 없으면 교사 화면에서 **새 방 생성 전에 경고**합니다. 기존 방은 유지됩니다.
- 이전에 이미 만든 방은 `minClientBuild`가 없으므로 호환성을 보존합니다. 구버전 강제 차단은 **v4.12 이후 새로 만든 방**에서만 보장됩니다.

## 설치 순서 (중요)
1. GitHub Pages 저장소 루트에 `purplekit-v4.12-upgrade.zip` 내부 파일들을 덮어씁니다. `version.json`과 새 `js/version.js`, `js/version-guard.js`도 반드시 올립니다.
2. GitHub Pages 배포 완료 후 교사 `rooms.html`을 Ctrl+Shift+R로 새로 고침합니다.
3. 교사 계정 로그인 후 `v4.12 전체 통합 보안 규칙 복사` 버튼을 클릭하여 **Firebase Console → Realtime Database → 규칙**에 기존 규칙 백업 후 전체 붙여넣기·게시합니다.
4. 교사 화면의 **권한 다시 확인**을 눌러 v4.12 규칙 적용을 확인하고 **새 방을 만듭니다.**
5. 학생들이 새 방 코드로 접속합니다. 처음에는 한 학생을 오래된 탭으로 접속시켜 서버가 접속 거부하는지 점검해 보세요.

## 주의 사항
- 클라이언트만 바꾸면 v4.11처럼 이미 열려 있는 탭은 업데이트 검사를 실행할 수 없습니다. 이번 기능은 **새 방 + Firebase 규칙 강제 검사**를 함께 사용합니다.
- 진행 중인 게임은 반드시 종료 후 배포하고, **새로 만든 v4.12 방**으로 수업을 시작하세요.
- 기존 문제 세트, 골드 17종의 보상 확률, 정답률 분석, 캐릭터 등은 변경하지 않았습니다.
- 버전 식별자와 Firebase 보안 규칙은 *실수로 남아 있는 구형 프로그램을 제한*하는 목적입니다. 악의적인 클라이언트에 대한 암호학적 무결성 인증은 아닙니다.
- `version.json`에 접근하지 못하면 새 방 입장이 제한되고, 재접속 후 재시도할 수 있습니다. 강제 새로고침에서 브라우저 캐시 우회 쿼리 매개변수가 붙습니다.

## 검증
로컬 자동 테스트와 JavaScript 문법 검사를 시행하며, 실제 Firebase 규칙 게시와 학교 기기 동시 접속 검증은 배포 후 수행해야 합니다.
