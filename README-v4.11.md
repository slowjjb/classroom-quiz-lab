# 퍼플킷 v4.11 — 상대 선택 지연·보상 확률 안내 개선

## 발견한 원인과 수정 사항
1. 교사의 보상 처리는 원래 학생 명단 순서대로 한 명씩 기다렸습니다. 상대 선택 요청이 이미 도착했어도 앞선 학생들의 채점·상자 지급이 모두 끝날 때까지 지연될 수 있었습니다. 이번 버전은 이미 도착한 학생의 **직접 상대 선택**을 우선 처리하고, 그 뒤 타임아웃 자동 선택 → 보물상자 지급 → 문제 채점 순으로 처리합니다. Firebase 보상 지급 트랜잭션 및 중복 지급 방지 로직은 그대로 유지합니다.
2. 이전 버전에서 교사 화면은 `/v4/targets/방코드` 아래에 누적되는 **전체 상대 선택 기록**을 실시간 구독했습니다. v4.11에서는 상대를 선택해야 하는 학생의 **그 문항 선택 기록 하나만** 잠시 구독하므로 사용 시간이 늘수록 데이터 읽기량이 불필요하게 커지는 현상을 줄였습니다.
3. 학생 상대 선택 화면에서 매 0.5초마다 모든 친구 목록과 골드를 확인하던 작업을 줄이고, 카운트다운만 업데이트합니다. 여러 Firebase 이벤트가 같은 프레임에 도착하면 화면 갱신을 묶어 처리합니다.
4. 한번 접수된 상대 선택을 학생이 다시 누르지 않게 막고, 확인 중임을 명확히 표시합니다. 선택이 접수된 후 교사 지급까지 약간의 시간이 걸리는 것은 가능하지만, 같은 문항을 중복 제출하지는 않습니다.
5. v4.10의 실제 추첨표는 '내 골드 **30% 잃기** 3%'였지만, 교사 설정의 오래된 **'50% 잃기 5%' 안내 문구**가 수정되지 않아 혼란을 일으켰습니다. 고정 문구 대신 실제 보상표에서 자동으로 계산된 숫자를 표시하도록 수정했습니다.
6. **상대 골드 50% 빼앗기 5%는 그대로 존재**합니다. 뺏긴 학생 입장에서는 보유 골드의 50%가 줄어들 수 있습니다. 이는 ‘내 골드 50% 잃기’ 추첨과 다릅니다.

## 적용 방법
1. v4.11 업그레이드 ZIP을 풀어 GitHub 저장소 루트에 내부 파일과 폴더를 업로드하고 커밋합니다.
2. GitHub Pages 배포 후 교사 `rooms.html`, 학생 `join.html`을 모두 `Ctrl+Shift+R`로 새로고침합니다.
3. 브라우저의 표시 버전이 **v4.11**인지 확인하고 **새 방**에서 두세 학생으로 상대 선택 보상을 검증합니다.
4. 진행 중인 수업 게임을 끝낸 다음 업데이트하세요. v4.10 진행 도중 파일을 바꾸는 것은 권장하지 않습니다.

## 유지되는 사항
- 총 17종 보상과 확률은 v4.10과 **동일**, 합계 100%입니다. 전부 잃기 0.05%, 내 골드 30% 잃기 3%, 내 골드 10% 잃기 8%입니다.
- 상대 골드 50% 빼앗기는 기존 5%입니다.
- Firebase **Realtime Database 보안 규칙 변경 없음** (v4.8 이후 규칙 그대로).
- 기존 문제 세트, CSV, 저장된 게임 기록과 학습 정답률 계산은 유지됩니다.

## 검증 범위
자동 테스트 및 문법 검사, 상태 전환 우선순위 단위 테스트를 통과했습니다. 실제 학교 네트워크와 20명 실시간 동시 접속 테스트는 이 파일만으로 재현할 수 없으므로 배포 후 확인이 필요합니다.
