# 퀴즈 실험실 v2 — 실시간 게임 방(교사/학생 대기실)

2026-11-10. 교실 실습용 **v2 업그레이드**입니다. 기존 v0 접속 확인·v1 CSV 문제 관리 데이터는 변경하지 않습니다.

## 현재 포함된 기능

- 교사 Google 로그인 권한 확인 및 v0+v1+v2 통합 보안 규칙 생성
- 새 방 만들기: 충돌 방지용 6자리 참여 코드, 운영 기준 인원(기본 25명, 제한이 아님)
- 모드 4종 지정(표시만; 실제 플레이는 v3~v6에 구현)
- v1에 저장된 문제 세트 선택(선택 결과만 방 정보에 기록; 실제 문제는 아직 학생에게 전송하지 않음)
- 참여 링크 복사 및 QR 코드 표시(외부 QR 생성 라이브러리 연결이 불가하면 참여 링크 복사 사용)
- 실시간 가상 학생 명단, 중복 브라우저 세션을 한 학생으로 집계
- 브라우저 새로고침 후 자동 재참여, 연결 해제 감지, 기존 참가자 재접속
- 입장 마감/다시 허용, 방 종료, 종료한 방 기록 삭제
- 교사 계정으로 방 목록 복원
- 서버에 저장된 v0/v1 데이터와 v2 데이터를 서로 다른 경로에 유지

## 설치: GitHub → Firebase → 게임 방 테스트

**1. 사전 백업:** GitHub의 v1 버전을 보존하려면 현재 코드를 ZIP으로 백업하거나 GitHub에서 커밋 이력을 기억해 둡니다. Firebase Realtime Database의 기존 규칙도 별도 복사해서 저장해 둡니다.

**2. GitHub에 업로드:** `quizlab-v2-upgrade.zip`을 압축 해제하고, 폴더 안의 `index.html`, `teacher.html`, `student.html`, `rooms.html`, `join.html`, `styles.css`, `js` 폴더의 새 파일, `README-v2.md`, `tests`를 업로드합니다. **상위 폴더(quizlab-v2 등) 자체를 저장소 안에 만들지 마세요.** `index.html`과 `rooms.html`은 저장소의 루트에 있어야 합니다. `Commit changes`를 누릅니다.

**3. 주의 — 제외된 파일:** 이 업데이트 ZIP에는 **`firebase-config.js`, `database.rules.json`, `js/firebase.js`, `js/sets.js`, `js/csv.js`, `js/student.js`, `js/teacher.js`가 없습니다.** 이미 정상인 Firebase 연결 정보와 기존 코드를 덮어쓰지 않기 위해서입니다.

**4. 교사 화면 확인:** `https://slowjjb.github.io/classroom-quiz-lab/rooms.html`에 접속합니다. Google 계정으로 로그인합니다. v2 규칙이 아직 적용되지 않았다면 “v2 규칙 필요”라는 안내가 나타납니다.

**5. Firebase 보안 규칙 적용:** 교사 화면에서 `전체 규칙 복사`를 누릅니다. Firebase Console → Realtime Database → **규칙**에서 기존 규칙 전체를 대체하고 **게시**합니다. 이 규칙에는 v0·v1 규칙도 포함됩니다. `".read": true`나 `".write": true`를 임의로 추가하지 마세요.

**6. GitHub 규칙 동기화:** 방금 Firebase에 게시한 **동일한 규칙**을 GitHub 저장소 `database.rules.json`에도 붙여넣고 커밋합니다. GitHub에 저장만 해서는 Firebase 보안 규칙이 바뀌지 않습니다.

**7. 권한 재확인:** `rooms.html`의 `권한 다시 확인`을 클릭하거나 새로고침합니다. `교사 권한 확인`이 나타나는지 확인합니다.

**8. 첫 방 만들기:** 방 이름 `v2 연결 테스트`, 목표 `25명`, 모드 `클래식`, 문제 세트는 `연결 시험용` 또는 v1 테스트 세트를 선택하고 `6자리 참여 코드로 방 만들기`를 클릭합니다.

**9. 학생 접속:** 별도의 크롬 시크릿 창(`Ctrl + Shift + N`)에서 `join.html`로 접속합니다. 교사 방의 6자리 코드와 `테스트학생01`을 입력하고 `게임 방 입장`을 누릅니다. 교사 화면에 1명이 표시되어야 합니다.

**10. 재접속·종료:** 학생 창에서 F5로 새로고침하여 자동 복원을 확인합니다. 학생 창을 닫으면 교사 명단에서 자동으로 사라지는지 확인합니다. 새 시크릿 창에서 같은 방식으로 재접속합니다. 교사 화면에서 `입장 마감` 후 신규 가상 학생이 들어올 수 없는지, 기존 가상 학생의 재접속은 가능한지, `방 종료` 후 신규 입장이 차단되는지 확인합니다. 종료한 방은 삭제해도 v1 문제 세트에는 영향이 없습니다.

## 중요한 제한

- **v2는 실시간 대기실입니다.** 아직 문제를 출제하거나 점수를 부여하지 않습니다. v3에서 실제 클래식 게임을 구축합니다.
- 룸 코드는 임의의 6자리 숫자이며 로그인 없는 공개 입장은 아닙니다(익명 Firebase 인증 사용). 다만 코드만 아는 익명 사용자가 입장할 수 있으므로 실제 학생 실명·민감정보를 넣지 마세요.
- 동일한 가상 이름을 다른 Firebase 익명 UID로 입력하면 두 학생으로 기록될 수 있습니다. **동일 UID의 여러 브라우저 탭만 인원 중복 집계를 방지**합니다. 교실 실사용 전 이름 중복 정책·인증 방식을 다시 확정해야 합니다.
- 등록된 학생의 이름(profile)은 방이 종료될 때까지 남지만 `connections` 값으로 현재 접속 중인지 판단합니다. 종료 후에는 교사만 방 삭제가 가능합니다.
- 방 생성 시간 및 출석 순서는 현재 클라이언트 시간을 사용하며 **평가·점수·부정행위 방지용 신뢰 데이터가 아닙니다.** 정답 판정과 점수 보상은 서버 측에서 검증하는 구조로 v3에 추가해야 합니다.
- 25명은 기본 운영 기준이며 입장을 강제로 막는 최대값이 아닙니다. 30명 이상의 안정성은 실제 동시 접속 테스트에서 확인해야 합니다.
- QR 표시에는 cdnjs의 qrcode-generator 1.4.4를 사용합니다. 해당 리소스가 차단되면 `참여 링크 복사`를 이용해 접속할 수 있습니다.
- `database.rules.json`에 들어가는 교사 UID는 비밀번호는 아니지만, 전체 프로젝트를 공개할 경우 해당 정보가 노출됩니다. 서비스 계정 키/관리자 비밀키는 GitHub에 올리면 안 됩니다.

## 소스 구조

- `rooms.html`, `js/rooms.js`: 교사용 방 관리
- `join.html`, `js/join.js`: 학생 참여/재접속
- `js/rules-v2.js`: v0·v1을 포함하는 v2 보안 규칙 생성기
- `styles.css`: 새 방 화면 레이아웃 추가 (v1 문제 편집 UI는 추후 개선)
- `index.html`, `teacher.html`, `student.html`: v2 이동 링크 및 버전 표기
- `tests/test-v2.mjs`: Node.js 정적 검사 (`node tests/test-v2.mjs`)

## 개발자 메모

- 실시간 로스터 경로: `v2/rooms/<code>/members/<uid>/connections/<session>`
- 방 정보: `v2/rooms/<code>/meta`
- 교사별 생성한 방 인덱스: `v2/hostRooms/<teacherUid>/<code>`
- 기존 `v0/presence` 및 `v1/questionSets` 경로는 건드리지 않음
- `onDisconnect.remove()` 예약 → 온라인 접속 기록 생성 순서. Realtime Database 서버는 onDisconnect 권한을 접속 예약 시와 실제 연결 해제 시 두 번 검사함.
- v3에서 점수, 보상, 정답 검증은 별도 서버 측 신뢰 실행 환경을 설계해야 함.
