# 퀴즈 실험실 v2.2 — 동시 접속 테스트 도구

## 이번 버전의 목적

v2.1에서 확인된 게임 방 생성·중복 이름 방지·입장 마감·방 종료 로직을 바꾸지 않고 **`loadtest.html`** 별도 페이지를 추가합니다. 목표는 교사 1명과 서로 다른 익명 UID를 가진 가상 학생 **5명 → 15명 → 30명**의 연결을 검증하는 것입니다.

- **단순 학생 목록 30행 생성이 아닙니다.** 가상 학생별로 `initializeApp(firebaseConfig, 서로 다른 앱 이름)`, `getAuth(app)` 및 `getDatabase(app)`를 각각 호출하므로 별도의 Firebase 인증 인스턴스와 DB 연결을 사용합니다.
- 가상 계정은 `inMemoryPersistence`를 사용하므로 기존 교사의 Google 로그인이나 일반 학생의 로그인 저장소에 영향을 주지 않습니다.
- 익명 사용자 생성은 과도한 인증 요청을 줄이기 위해 **최대 3개씩** 병렬로 실행합니다. 계정 30개를 준비한 후 **입장 요청 30개를 한꺼번에 보냅니다.**
- 실제 v2.1과 동일한 이름 선점 트랜잭션, `members/<UID>/profile`, `connections/<세션>` 및 `onDisconnect` 방식을 사용합니다.
- 결과에는 입장 성공·실패, 고유 UID/이름/세션 수, 입장 평균·95백분위 시간, 연결 끊김 및 재접속 결과를 표시합니다.
- 모든 테스트 데이터는 **v2/rooms/<전용 방 코드>** 내부에 별도로 보관합니다. 교사 전용 `hostRooms` 색인도 함께 관리합니다. v0 기록, v1 문제, 일반 수업 방은 건드리지 않습니다.
- 테스트 전용 방에는 `testOnly:true`를 저장하고, **정리하기 전에 이를 교사 권한으로 서버에서 재확인합니다.**

## 설치 방법

1. `quizlab-v2.2-upgrade.zip`을 내려받아 압축을 풉니다.
2. GitHub 저장소 `https://github.com/slowjjb/classroom-quiz-lab` → **Add file → Upload files**로 ZIP 안의 파일과 폴더를 올리고 `Commit changes`를 누릅니다. ZIP 자체를 올리면 안 됩니다.
3. `https://slowjjb.github.io/classroom-quiz-lab/loadtest.html`에 접속합니다. **v2.2 버전 표기**를 확인합니다. 이전 버전이 보이면 새 탭으로 열거나 강력 새로고침합니다.
4. 교사 Google 계정으로 로그인되어 있으면 자동 권한 검사를 진행합니다. 안 되어 있으면 Google 로그인 버튼을 누릅니다.
5. **Firebase 보안 규칙 업데이트 불필요.** 이번 테스트는 기존 v2.1에서 실제로 동작한 규칙을 그대로 사용합니다. `firebase-config.js`, `database.rules.json`은 교체하지 마세요.

## 5 → 15 → 30명 테스트

각 인원 시험은 **새 테스트 방**에서 진행합니다.

1. **새 테스트 방 만들기**를 누르고 6자리 코드가 생성되는지 확인합니다. 이전에 만든 일반 게임 방은 선택할 수 없습니다.
2. **가상 학생 수**에서 먼저 **5명**을 선택합니다.
3. **가상 학생 준비**를 누릅니다. 준비는 인증 과정이므로 교사 대기실에는 아직 온라인 학생이 없습니다. 인증 제한이 나타나면 반복 누르지 말고 오류 메시지를 확인합니다.
4. **동시 입장 실행**을 누릅니다. 교사 화면의 상태 수치가 5명, 고유 UID 5개, 고유 이름 5개, 세션 5개인지 확인합니다.
5. **5명 연결 끊기·복구**를 눌러 오프라인 전환과 UID를 유지한 재접속을 시험합니다.
6. **현재 상태 재검사**를 눌러 데이터가 일치하는지 확인합니다.
7. **테스트 결과 CSV 저장** 버튼을 눌러 보고서를 저장합니다.
8. **테스트 종료 및 방 정리**를 누릅니다. 테스트 방과 이름·접속 기록을 삭제하고, 생성한 익명 인증 계정도 개별 삭제를 시도합니다. 인증 계정 삭제 실패가 있을 경우 실행 기록을 확인합니다.
9. 같은 과정을 15명과 30명에 반복합니다.

**중요:** 30명을 한꺼번에 인증 생성하는 것은 아닙니다. 30개 계정을 준비한 후에 30명이 **동시에 방에 입장하도록 요청**하는 구조입니다. 학교 네트워크/기기 검증은 실제 태블릿 여러 대로 추가해야 합니다.

## 주의 사항

- **가상 사용자만** 사용합니다. 실제 학생 이름·학습 결과가 필요한 테스트는 아닙니다.
- Firefox/Chrome의 개인정보 보호 설정, 광고 차단 도구, 네트워크 품질, Firebase 익명 계정 생성 제한으로 일부 연결이 실패할 수 있습니다. 그럴 경우 오류 수를 그대로 기록하며, 성공으로 간주하지 않습니다.
- 하나의 브라우저에서 Firebase 연결 30개를 만들더라도 **30대의 개별 태블릿과 Wi-Fi 특성을 재현한 것은 아닙니다.** 실사용 전에는 실제 학생 기기 여러 대에서 QR·새로고침·접속 종료를 추가 검증하세요.
- 테스트 중 탭을 닫으면 `onDisconnect`가 연결 세션을 종료하지만 **프로필과 이름 예약은 남을 수 있습니다.** 같은 도구를 다시 열면 **이전에 남은 테스트 방 → 잔여 테스트 방 정리**로 삭제할 수 있습니다.
- 익명 인증 계정 삭제는 Firebase 네트워크 오류로 실패할 수 있습니다. 보고서에 삭제 성공·실패를 기록하므로, 실패 시 Firebase Authentication의 사용자 목록도 확인하세요.
- 결과 보고서를 받은 후 테스트 데이터를 삭제하는 순서를 권장합니다.
- v2.2는 테스트 기능만 추가합니다. 실제 문제 출제·정답·순위 등은 v3에서 구현할 예정입니다.

- `index.html`, `rooms.html`, `teacher.html`: 테스트 페이지 접근 링크

- `README-v2.2.md`: 이 안내서
