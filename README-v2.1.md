# 퀴즈 실험실 v2.1 — 중복 이름 방지 안정화 패치

본 버전은 **v3 클래식 게임 이전의 v2 안정화 패치**입니다. 기존 v0 교사·학생 연결, v1 문제 세트, v2 방 만들기 기능을 삭제하지 않습니다.

## 무엇이 달라졌나요?

1. **방 안의 이름 중복 입장 차단:** 다른 기기·다른 익명 Firebase UID가 이미 사용한 이름을 등록하려고 하면 입장을 거부합니다.
2. **동시 충돌 방지:** `v2/rooms/<참여코드>/nameClaims/<이름>` 경로를 Firebase 트랜잭션으로 선점하므로 두 학생이 같은 순간 같은 이름으로 등록하려 해도 한 UID만 선점할 수 있게 설계했습니다.
3. **서버 보안 규칙:** 단순한 화면 검사에 그치지 않고, 해당 이름의 소유 UID와 학생 프로필·접속 기록의 UID를 Firebase 규칙에서 함께 확인합니다.
4. **재접속 유지:** 같은 익명 UID는 이름 선점을 유지하므로 새로고침/인터넷 재연결/입장 마감 후 복귀할 수 있습니다.
5. **오프라인 이름 해제:** 학생 창을 닫거나 `대기실 나가기`를 눌러 접속을 끊어도 이름은 재접속을 위해 예약됩니다. 교사는 방 화면의 오프라인 학생 항목에서 **이름 해제** 버튼으로 그 예약을 풀 수 있습니다.
6. **v2.1 규칙 확인:** 예전 v2 보안 규칙이 활성화되어 있으면 교사 화면에서 v2.1 통합 규칙 게시를 요청합니다.

영어 이름은 소문자로 통일하며, 전각 문자와 연속 공백도 정리합니다. Firebase 경로에 사용할 수 없는 문자(`. # $ [ ] /`)는 이름에 넣을 수 없습니다. 테스트에는 가상 학생 이름만 사용하세요.

## 적용 순서 (중요)

### 1) GitHub 파일 업로드

- `quizlab-v2.1-upgrade.zip`을 **압축 해제**합니다.
- [GitHub 저장소](https://github.com/slowjjb/classroom-quiz-lab) → `Add file` → `Upload files`로 압축을 푼 **내용물**을 업로드합니다.
- `join.html`, `rooms.html`, `index.html`, `student.html`, `teacher.html`, `js/` 내부 변경 파일, `README-v2.1.md`, 테스트 파일이 저장소 최상위의 기존 경로로 올라가야 합니다.
- `Commit changes`를 누릅니다.
- **`firebase-config.js`와 `database.rules.json`을 덮어쓰지 마세요.** 업그레이드 ZIP에는 두 파일을 포함하지 않았습니다.

### 2) Firebase의 보안 규칙 업데이트 (반드시 필요)

- 새 페이지 `https://slowjjb.github.io/classroom-quiz-lab/rooms.html`를 엽니다.
- 교사 로그인 상태에서 **`v2.1 규칙 필요`**가 표시되는지 확인합니다. 이전 v2 규칙은 작동하더라도 이름 중복을 막지 못합니다.
- 안내 영역의 **`전체 규칙 복사`**를 누릅니다.
- [Firebase Console](https://console.firebase.google.com/) → 프로젝트 `classroom-quiz-lab` → **Realtime Database → 규칙**으로 들어갑니다.
- 현재 규칙을 별도 텍스트 파일로 백업한 후, 전체를 복사한 v2.1 규칙으로 바꾸고 **게시**합니다.
- 새 규칙은 v0 + v1 + v2.1 기능을 포함합니다. 최상위 `.read`/`.write`를 `true`로 바꾸지 마세요.
- 교사 `rooms.html` 화면에서 `권한 다시 확인`을 누릅니다. **교사 권한 확인**이 나타나면 다음 단계로 진행합니다.

### 3) GitHub 보안 규칙 동기화

- **Firebase에 게시한 것과 정확히 같은 JSON 내용**을 GitHub의 `database.rules.json`에도 붙여넣고 `Commit changes`로 저장합니다.
- GitHub에 이 규칙을 저장하는 것만으로는 Firebase 규칙이 적용되지 않습니다. 반드시 위 2단계를 먼저 완료하세요.

### 4) 테스트는 새로운 방에서!

- **기존 v2.0 방의 중복 이름 프로필은 자동으로 지우지 않습니다.** 구버전 방은 이미 중복 가입된 상태일 수 있으므로 **v2.1 테스트용 새 방**을 만들어 검증하세요.
- 별도 PC/휴대전화로 두 번째 이름 중복을 시험할 때는 다른 브라우저의 익명 로그인 계정이 필요합니다. 크롬 시크릿 창과 휴대전화는 별도 계정으로 작동합니다.

### 이름 예약 정책

- **단순히 창을 닫거나 `대기실 나가기`를 누르는 것만으로는 이름을 반환하지 않습니다.** 같은 학생이 연결을 복구할 수 있도록 남겨둡니다.
- 학급에서 기기를 바꾸거나 이름 예약이 남아 입장이 막힌 경우, 교사가 해당 학생이 **오프라인**임을 확인하고 `이름 해제`를 누릅니다. 그 후 다른 기기로 같은 이름을 등록할 수 있습니다.
- 교사에게 표시되는 **오프라인 학생**은 실시간 인원 수에는 포함되지 않습니다.
- 영문 대소문자·띄어쓰기 정규화는 정상적인 브라우저를 대상으로 합니다. 악의적으로 조작된 클라이언트나 시각적으로 비슷한 유니코드 이름까지 완벽히 동일인으로 판정하는 신원 인증 시스템은 아닙니다.

## 주의 및 미검증 사항

- 현재 구현은 실시간 대기실 안정화용입니다. 문제 출제, 정답 판정, 점수는 **v3**에서 별도 개발합니다.
- 클라이언트 코드 및 Firebase 규칙의 **정적 검사**는 통과했지만, 사용자의 실제 Firebase에 연결한 **동시 경합·방 간 이동·다중 기기 통합 테스트는 아직 수행하지 않았습니다.** 적용 후 반드시 위 절차로 검증해야 합니다.
- `nameClaims`의 고아 예약이 남거나 비정상 프로필이 발생하면 교사 오프라인 이름 해제로 정리할 수 있습니다.
- 업로드 후 버전 표시가 이전 v2라면 PC에서 `Ctrl + F5`로 강력 새로고침하고, 휴대전화에서도 페이지를 다시 여세요.
- 25명은 기본 기준 인원이며 최대 인원 제한이 아닙니다. 30개 이상 동시 접속 부하 검증은 아직 남아 있습니다.
- 실제 학생 개인정보는 테스트 시스템에 입력하지 마세요.
