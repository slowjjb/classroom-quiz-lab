# 퀴즈 실험실 v3 · 클래식 퀴즈 시범판

> 기존 v0·v1·v2.1·v2.2를 유지하면서 **클래식 동시 출제 / 첫 시도 채점 / 순위표 / 정답률 / CSV 결과**를 추가합니다.
>
> 반드시 **가상 학생**으로 테스트하세요. 실제 학생 사용 전 운영·보안·네트워크 검증이 필요합니다.

## 1. 기존 프로젝트에 덮어쓰는 순서

1. `quizlab-v3-upgrade.zip`을 압축 해제합니다.
2. GitHub 저장소 `slowjjb/classroom-quiz-lab`의 **Add file > Upload files**로 압축 해제한 파일과 `js/`, `tests/` 폴더를 함께 올립니다.
3. 같은 파일명은 수정으로 처리하고 `Commit changes`를 누릅니다.
4. 이번 ZIP에는 `firebase-config.js` 및 `database.rules.json`을 **넣지 않았습니다.** 기존 Firebase 설정과 교사 UID는 유지됩니다.
5. https://slowjjb.github.io/classroom-quiz-lab/rooms.html 접속 → 브라우저의 `Ctrl+Shift+R`을 누릅니다. 게임 방 관리에 **v3 · 클래식 퀴즈 진행** 패널이 보여야 합니다.

## 2. v3 보안 규칙 적용 (필수)

1. 교사 Google 계정으로 `rooms.html`에 로그인합니다.
2. 기존 또는 새 게임 방을 열면 `v3 규칙 필요` 안내가 나옵니다.
3. **v3 전체 규칙 복사/다운로드** 버튼을 누릅니다. 교사 UID가 포함된 v0+v1+v2.1+v3 통합 규칙이 생성됩니다.
4. Firebase 콘솔 → **Realtime Database > 규칙** → 기존 내용을 **전체 교체**하여 **게시**합니다.
5. GitHub 저장소의 `database.rules.json`에도 **같은 전체 규칙을 붙여넣고 Commit**합니다.
6. 게임 방 관리 화면에서 **권한 다시 확인** 또는 `Ctrl+Shift+R`로 확인합니다.

주의: **v3 규칙만 따로 덧붙이지 마세요.** 기존 기능이 중단되지 않도록 전체 규칙을 교체해야 합니다.

## 3. 실제 테스트: 교사 1명 + 가상 학생 1명

1. `sets.html`에서 기존에 저장된 **정상_테스트_20문항**이 있는지 확인합니다. (없으면 v1 테스트 CSV를 업로드해 저장)
2. `rooms.html`에서 **클래식** 모드 및 위 문제 세트를 선택해 새 게임 방을 만듭니다. **문제 세트 선택 안 함**으로 만들면 퀴즈를 시작할 수 없습니다.
3. 크롬 시크릿 창에서 `join.html` 열고 참여 코드, `테스트학생1` 입력하여 입장합니다.
4. 교사 화면에서 **게임 준비 및 입장 마감**을 누르고 **다음 문제 출제**를 눌러 1번 문제를 출제합니다.
5. 학생 화면에 같은 문제와 보기만 표시되는지 확인합니다. 학생이 정답 제출을 누릅니다.
6. 교사 화면에 **제출 1명**, 순위와 문항별 제출 인원이 반영되는지 확인합니다.
7. **정답 공개** 후 학생 화면에 정답 및 채점 결과가 나오는지 확인합니다.
8. **다음 문제 출제**로 2번 문제를 진행하고 주관식도 시험합니다.
9. 교사는 **학생별 결과 CSV**를 다운로드합니다. 점수와 실제 정답률은 구분해서 확인합니다.
10. **게임 종료** 후 기존 `방 종료`를 누르고, 필요하면 저장된 결과 CSV를 보관한 뒤 테스트 방을 삭제합니다.

## 4. 재접속·제한 시간 검사

- 학생 새로고침 → 같은 방, 같은 UID로 재접속, **이미 제출한 문항에 다시 제출되지 않아야 함**
- 같은 학생이 같은 문제 제출 버튼을 두 번 클릭 → **DB 답안 경로 최초 제출 1회만 허용**
- 시간 종료 → 새 답안이 거부되고 교사가 정답을 공개
- **일시 정지** → 학생 제출 차단, **재개** 후 남은 시간부터 진행
- **10초 연장** → 제한 시간이 연장되는지 확인
- 교사 화면 새로고침 → 저장된 문제/점수/채점 기록으로 복구 (게임 중 탭을 닫으면 채점·진행이 지연될 수 있음)

## 5. 데이터 구조 및 보안

- **정답 원본:** `v1/questionSets`, `v3/privateRuns` → 교사 Google UID만 읽기·쓰기 허용
- **현재 출제 중인 문제:** `v3/public/<code>` → 방 구성원은 문제·보기만 읽음. 정답은 **정답 공개 상태**에서만 전송
- **학생 제출:** `v3/answers/<code>/<round>/<uid>` → 방에 등록된 익명 UID는 진행 중 문제에 한 번만 쓰기 가능. Firebase 서버 시각으로 마감 검증
- **교사 채점:** `v3/grades/<code>` → 교사만 기록; 학생은 문제 종료 후 자신의 채점 결과만 읽기 가능
- **순위:** `v3/scores/<code>` → 교사만 쓰기; 방 참가 학생은 읽기 가능

점수는 정답일 때 **기본 500점 + 속도 보너스 최대 500점**, 오답/시간 초과는 **0점**입니다. 실제 성취도는 점수와 별도로 정오답·정답률로 확인합니다.

## 6. 아직 남아 있는 제약과 테스트

1. **완전한 서버 측 채점은 아닙니다.** 무료 Spark 요금제의 추가 결제 설정 없이 작동하도록 **교사가 인증된 브라우저**가 정답을 판정하고 기록하는 시범 구조입니다. 학생은 정답 데이터나 점수 쓰기 권한을 받지 않습니다. 교사 브라우저가 종료되면 자동 채점·문제 진행이 지연될 수 있습니다. 실제 수업 운영 전에 독립 서버 채점 구조로 전환 여부를 결정해야 합니다.
2. **30명 동시 답안 제출 테스트는 아직 완료되지 않았습니다.** v2.2에서 검증된 30명 동시 접속과 별개입니다.
3. **실제 태블릿 30대의 Wi-Fi 테스트는 미실시** 상태입니다.
4. 기존 `방 삭제`는 `v2` 대기실을 정리합니다. `v3`의 교사 전용 학습 결과는 자동 삭제하지 않고 보존합니다. 장기 보관·삭제·회차 비교는 후속 분석 버전에서 처리해야 합니다.
5. 현재 앱에는 문제 이미지를 첨부하는 기능이 없습니다.
6. 순위는 교사가 채점을 처리하는 속도에 따라 약간 늦게 반영될 수 있습니다.

## 7. 이전 버전으로 되돌리기

GitHub의 커밋 기록을 이용하여 v2.2로 되돌릴 수 있습니다. **Firebase 보안 규칙을 먼저 삭제하거나 전체 공개(`.read:true`, `.write:true`)로 바꾸지 마세요.** 기존 데이터는 삭제되지 않도록 관리하세요.
