# 퀴즈 실험실 v3.2 — 자동 공개·보기 색상·문제 이미지

v3.1에서 정상 작동한 클래식 문제 출제, 교사 채점, 학생별 정오답, 실시간 순위, 결과 CSV 기능을 유지하면서 다음 기능을 추가했습니다.

1. **새 문제의 보기 선택 초기화** — 이전 문항에서 4번을 눌렀더라도 다음 문항에서는 아무것도 선택되지 않습니다. 같은 문항에서 Firebase 상태가 갱신될 때는 아직 제출하지 않은 선택을 유지합니다.
2. **자동 정답 공개** — 기본값 켜짐. 참여 명단 중 **현재 온라인인 학생**과 **이미 답을 제출한 학생**이 모두 제출했고 교사 컴퓨터에서 채점까지 완료되면 약 1초 후 정답을 공개합니다. 전원 제출이 아니더라도 **제한 시간이 지나면 자동 공개**합니다. 인터넷이 끊겨 오프라인이 된 *미제출* 학생은 전원 제출 조건에 포함하지 않습니다. 처음부터 접속 학생이 전혀 없으면 전원 제출로 자동 공개하지 않습니다.
3. **자동 공개 켜기/끄기** — 교사 관리 화면과 큰 진행 화면의 체크박스에서 설정하며, 해당 게임의 `v3/privateRuns/<참여코드>/autoReveal`에 보존합니다. 꺼 놓으면 시간 종료 뒤에도 교사가 직접 `정답 공개`를 눌러야 합니다.
4. **네 가지 보기 색상** — 파랑, 보라, 노랑, 하늘색. **초록색은 정답, 빨간색은 오답을 나타낼 때만** 사용합니다. 색상 외에도 숫자와 정답 문구를 표시합니다.
5. **문제 이미지** — GitHub Pages의 `images/questions/`에 공개 이미지 PNG/JPG/JPEG/WebP를 올리고, 문제 관리 화면의 각 문항에 **이미지 파일명 또는 주소**를 입력합니다. 교사·학생 큰 문제 화면 및 학생 정답 공개 화면에 표시됩니다.

## 설치 방법

1. **게임 진행 중에는 업그레이드하지 마세요.** 기존 게임 종료 및 결과 CSV 저장 후 작업을 시작하세요.
2. `quizlab-v3.2-upgrade.zip`을 압축 해제합니다. **압축 파일 자체가 아니라 안의 파일과 폴더**를 GitHub 저장소 `slowjjb/classroom-quiz-lab`의 `main` 최상위 위치에서 `Add file → Upload files`로 업로드합니다. `js`, `tests`, `images/questions` 폴더도 함께 올립니다.
3. `Commit changes`를 누릅니다. 기존 파일을 같은 경로에 덮어쓰되 **`firebase-config.js`, `database.rules.json`은 업그레이드에 포함하지 않았으므로 그대로 둡니다.** **Firebase Realtime Database 규칙을 새로 게시할 필요도 없습니다**(기존 v3 규칙 재사용).
4. 사이트의 `rooms.html`, `join.html`에서 **v3.2** 표시를 확인합니다. 윈도우 크롬에서는 `Ctrl+Shift+R`로 강력 새로고침, 모바일에서는 이전 탭을 닫고 QR을 다시 열어 주세요.
5. 테스트용 문제 세트를 선택해 **새 게임 방**을 만들고, 가상 학생 2명으로 검증한 뒤 실제 학급에서 사용하세요.

## 이미지 연결: 단계별 예시

1. GitHub 저장소에서 `images/questions/` 폴더를 열고 `Add file → Upload files`로 그림 `my-geometry.png`를 올립니다. 같은 폴더의 제공된 `v32-example-shape.png`는 기능을 확인하기 위한 예시입니다.
2. 이미지가 게시된 뒤 `https://slowjjb.github.io/classroom-quiz-lab/images/questions/my-geometry.png`에 접속해 실제로 그림이 표시되는지 확인합니다. 파일은 **공개**되므로 개인정보가 있는 이미지는 사용하지 마세요.
3. **문제 세트 관리 (`sets.html`)**에서 문제 세트를 불러오고 이미지가 필요한 문항의 **문제 이미지** 입력칸에 `my-geometry.png`만 입력합니다. (또는 `images/questions/my-geometry.png`나 해당 GitHub Pages 주소 전체도 가능.)
4. 이미지 미리보기를 확인하고 **문항 오류 다시 검사 → Firebase에 저장**을 누릅니다. 기존 세트를 불러온 뒤 저장하면 같은 세트가 수정됩니다. *이미 시작된 방의 문제는 준비 시점에 복사해 두므로*, 적용하려면 새 게임 방을 만들고 `게임 준비 및 입장 마감`을 다시 진행해야 합니다.
5. 학생이 문제를 풀 때 그림이 보이는지 확인합니다. 속도가 걱정되면 그림을 가급적 **100~300KB**로 압축하세요. 도형의 선과 글자가 흐려지지 않도록 합니다.

**중요 — CSV 호환성:** 기존 블루킷 10열 A~J 형식은 그대로 유지합니다. 이미지 주소는 CSV에 새 열을 추가하지 않고 Firebase 문제 세트의 `imageUrl` 속성에 보관합니다. **CSV 내보내기로는 이미지 연결이 함께 나가지 않습니다.** 이미지가 달린 세트를 CSV로 내려받을 때는 이 사실을 경고합니다. 이미지 파일 자체도 GitHub 저장소에 별도로 보관해야 합니다.

**이미지 보안:** `images/questions/` 폴더의 동일 사이트 이미지 주소만 허용합니다. 외부 사이트, SVG, 스크립트 URL은 받지 않습니다. 파일 이름에 정답을 노출하는 표현은 피하세요. 공개 GitHub 저장소에 올린 이미지는 누구나 접근할 수 있습니다.

## 권장 테스트

1. 학생 A가 1번 문항의 **4번**을 선택한 후 답을 제출합니다. 교사가 다음 문항을 출제하면 **4번이 선택되지 않은 상태**인지 확인합니다.
2. 새 방에 가상 학생 2명을 접속시키고 둘 다 답안을 제출합니다. 교사 브라우저를 열어 둔 상태에서 **자동으로 정답이 공개**되는지 확인합니다. 결과의 정오답과 점수를 확인합니다.
3. 다음 문항에서 한 학생만 답을 제출합니다. **제한 시간이 지나면 자동 공개**되는지 확인합니다.
4. 교사 화면에서 **자동 공개 체크박스를 끈 뒤**, 제한 시간이 지나도 자동 공개되지 않고 직접 `정답 공개`를 누를 수 있는지 확인합니다.
5. 이미지 예시를 한 문항에 연결하고, 교사·학생 화면 및 학생 정답 화면에서 그림이 보이는지 확인합니다.
6. 학생 새로고침, 결과 CSV, 게임 종료 후 방 삭제 기능이 종전과 같이 동작하는지 확인합니다.

## 현재 검증 결과 / 남은 한계

- 기존 v0~v3.1의 계산/파일/규칙 테스트 통과.
- v3.2 이미지 주소 검증, 블루킷 CSV 10열 보존, 자동 공개 온라인/오프라인 조건, 화면 ID 정적 테스트 통과.
- 브라우저 DOM 시뮬레이션에서 **새 문제 선택 초기화 → 이미지 표시 → 정답 공개 → 결과 확인**, 교사 자동 공개(2명 제출/2명 채점) 확인.
- **실제 Firebase에 연결한 25~30명 동시 답안 제출**, 실제 모바일 네트워크 불안정 상황, 이미지 여러 장의 학교 Wi-Fi 성능은 아직 검증하지 않았습니다.
- 채점과 자동 공개는 계속 **교사 브라우저가 담당**하므로 교사 브라우저를 닫거나 절전 상태에 두면 중단·지연될 수 있습니다.
- 기존 문제 편집 화면의 전체적인 여백 축소는 이번 버전에서 포함하지 않았습니다.

문제가 있으면 GitHub에서 이전 v3.1 커밋의 **프런트엔드 파일**로 복구할 수 있습니다. 테스트 중인 Firebase 문제 세트/학생 답안 기록은 임의로 삭제하지 마세요.
